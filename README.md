# JRNY Plan

JRNY Plan helps groups agree on an event time without a long message thread. A
host proposes exact times or a rough window, participants mark their
availability, and the host confirms the final time from the ranked overlap.

[Open the live app](https://flippant-bat-602.convex.site)

## Features

- Google sign-in through Convex Auth
- Public schedules and email-restricted invited schedules
- Exact candidate times or generated candidates from a rough date range
- Realtime availability ballots and best-overlap ranking
- Host-controlled voting deadlines and final-time confirmation
- Optional Google Calendar free/busy checks without reading event details
- AgentMail invitations, confirmation messages, and test-recipient suppression
- Idempotent schedule creation from signed AgentMail webhooks
- A machine-readable email protocol at `/llms.txt`

## Requirements

- Node.js 22 or later
- npm
- A Convex account and development deployment
- Google OAuth credentials for sign-in

AgentMail and Google Calendar access are optional during local feature work.
Their configuration is required only when you exercise those integrations.

## Run the app locally

Install the dependencies:

```bash
npm install
```

Connect the repository to a Convex development deployment. The Convex CLI
creates `.env.local` and sets `VITE_CONVEX_URL`:

```bash
npx convex dev --once
```

Configure the required Convex Auth keys and Google OAuth credentials on that
deployment. `npx @convex-dev/auth` generates `AUTH_PRIVATE_KEY` and `AUTH_JWKS`.
Set the Google values with the Convex CLI:

```bash
npx convex env set AUTH_GOOGLE_CLIENT_ID '<google-client-id>'
npx convex env set AUTH_GOOGLE_CLIENT_SECRET '<google-client-secret>'
```

Start both Convex and Vite:

```bash
npm run dev
```

Vite serves the app at `http://localhost:3000` by default.

## Configuration

Convex deployment variables control the backend integrations:

| Variable                        | Purpose                                                                                              |
| ------------------------------- | ---------------------------------------------------------------------------------------------------- |
| `AUTH_PRIVATE_KEY`              | Signs Convex Auth tokens. Generated by the Convex Auth setup command.                                |
| `AUTH_JWKS`                     | Publishes the matching JSON Web Key Set. Generated with the private key.                             |
| `AUTH_GOOGLE_CLIENT_ID`         | Identifies the Google OAuth application.                                                             |
| `AUTH_GOOGLE_CLIENT_SECRET`     | Authenticates the Google OAuth application.                                                          |
| `APP_URL`                       | Sets the public application origin for OAuth redirects, schedule links, and email replies.           |
| `CALENDAR_TOKEN_ENCRYPTION_KEY` | Encrypts stored Google Calendar tokens. Supply a base64-encoded 32-byte key.                         |
| `AGENTMAIL_API_KEY`             | Enables AgentMail delivery and inbound replies.                                                      |
| `AGENTMAIL_INBOX_ID`            | Selects the AgentMail inbox used for messages and `/llms.txt`.                                       |
| `AGENTMAIL_WEBHOOK_SECRET`      | Verifies signed inbound AgentMail webhook requests.                                                  |
| `E2E_PASSWORD_AUTH_ENABLED`     | Enables the test-only password provider on an allowlisted deployment. Never enable it in production. |
| `E2E_TEST_EMAILS`               | Allowlists test identities and suppresses outgoing mail to them.                                     |

Convex provides `CONVEX_SITE_URL`. The frontend reads `VITE_CONVEX_URL` from
`.env.local`.

## Project structure

```text
convex/          Convex schema, auth, schedules, calendar, email, and HTTP code
e2e/             Playwright multi-user browser scenarios
public/          Static assets, app icons, web manifest, and /llms.txt
scripts/         Test-environment checks
shared/          Framework-independent schedule parsing and validation
src/components/  Shared React components
src/routes/       TanStack Router pages
src/scheduling/   Client-side schedule draft state
tests/            Unit and Convex integration tests
```

The main routes are `/` for the landing page and dashboard, `/new` for schedule
creation, and `/s/:slug` for participation and final confirmation.

## Email schedule requests

JRNY Plan can create a schedule from a structured plain-text email. The sender
must already have a verified JRNY Plan account. The deployed `/llms.txt`
endpoint publishes the current inbox and request format when AgentMail is
configured.

The protocol uses one JSON object between `JRNY_SELECT_REQUEST_V1` and
`END_JRNY_SELECT_REQUEST`. The legacy marker names remain stable so existing
clients do not break after the product rename.

See [the email request architecture decision](./docs/adr/0001-authenticated-email-schedule-requests.md)
for the trust model and processing rules.

## Testing

Run the backend and unit tests with `npm test`. The suite covers schedule
lifecycle rules, access control, draft generation, calendar token handling,
email delivery, webhook verification, and inbound request idempotency.

The Playwright suite drives one host and two participants through invited and
public schedules. It uses a test-only password provider and reserved `.test`
identities. Follow [the end-to-end testing guide](./docs/e2e-testing.md) before
running `npm run test:e2e`.

## Build and deploy

Create the production bundle, then deploy the static client:

```bash
npm run build
npm run deploy
```

The Vite configuration prerenders `/` and emits an SPA fallback. Convex Static
Hosting serves the frontend after the exact authentication, calendar, webhook,
and `/llms.txt` HTTP routes.
