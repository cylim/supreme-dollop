# JRNY Plan

JRNY Plan helps signed-in groups agree on event times and other questions. A
host can propose candidate times for availability ballots or create a decision
with labeled options.

[Open the live app](https://flippant-bat-602.convex.site)

## Features

- Google sign-in through Convex Auth
- Public schedules and email-restricted invited schedules
- Exact candidate times or generated candidates from a rough date range
- Realtime availability ballots and best-overlap ranking
- Host-controlled voting deadlines and final-time confirmation
- Optional Google Calendar free/busy checks without reading event details
- AgentMail invitations, confirmation messages, and test-recipient suppression
- Standalone and schedule-attached decisions with single or multiple selection
- Optional decision deadlines and host-controlled close
- Idempotent schedule and decision creation from signed AgentMail webhooks
- A machine-readable email protocol at `/llms.txt`

## Requirements

- Node.js 26
- npm
- A Convex account and development deployment
- Google OAuth credentials for sign-in

AgentMail and Google Calendar access are optional during local feature work.
Their configuration is required only when you exercise those integrations.

## First-time local setup

1. Install the dependencies.

```bash
npm install
```

2. Connect the repository to a Convex development deployment.

```bash
npx convex dev --once
```

The Convex CLI creates `.env.local` and sets `VITE_CONVEX_URL`. If the first
sync reports missing auth variables, continue to the next step and then sync
again.

3. Generate the signing keys for Convex Auth.

```bash
npx @convex-dev/auth
```

This command sets `AUTH_PRIVATE_KEY` and `AUTH_JWKS` on the selected Convex
deployment.

4. Create a Google OAuth web client, then set its credentials on the same
   deployment.

```bash
npx convex env set AUTH_GOOGLE_CLIENT_ID '<google-client-id>'
npx convex env set AUTH_GOOGLE_CLIENT_SECRET '<google-client-secret>'
npx convex env set APP_URL 'http://localhost:3000'
```

Keep OAuth credentials in Convex deployment variables. Do not add them to
`.env.local` or commit them.

5. Start Convex and Vite.

```bash
npm run dev
```

Open `http://localhost:3000`. The terminal reports when Convex has synced and
Vite is ready.

AgentMail and Calendar connections are not required to start the app. To test
Calendar connections, set `CALENDAR_TOKEN_ENCRYPTION_KEY` to a base64-encoded
32-byte key:

```bash
openssl rand -base64 32
npx convex env set CALENDAR_TOKEN_ENCRYPTION_KEY '<generated-key>'
```

To enable email delivery, set the three `AGENTMAIL_*` variables listed below
and register `/agentmail/webhook` with AgentMail.

## Configuration

Convex deployment variables control the backend integrations:

| Variable                        | Purpose                                                                                                                                              |
| ------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
| `AUTH_PRIVATE_KEY`              | Signs Convex Auth tokens. Generated by the Convex Auth setup command.                                                                                |
| `AUTH_JWKS`                     | Publishes the matching JSON Web Key Set. Generated with the private key.                                                                             |
| `AUTH_GOOGLE_CLIENT_ID`         | Identifies the Google OAuth application.                                                                                                             |
| `AUTH_GOOGLE_CLIENT_SECRET`     | Authenticates the Google OAuth application.                                                                                                          |
| `APP_URL`                       | Sets the public application origin for OAuth redirects, schedule links, and email replies.                                                           |
| `CALENDAR_TOKEN_ENCRYPTION_KEY` | Encrypts stored Google Calendar tokens. Supply a base64-encoded 32-byte key.                                                                         |
| `AGENTMAIL_API_KEY`             | Enables AgentMail delivery and inbound replies.                                                                                                      |
| `AGENTMAIL_INBOX_ID`            | Selects the AgentMail inbox used for messages and `/llms.txt`.                                                                                       |
| `AGENTMAIL_WEBHOOK_SECRET`      | Verifies signed inbound AgentMail webhook requests.                                                                                                  |
| `E2E_PASSWORD_AUTH_ENABLED`     | Enables the test-only password provider on an allowlisted deployment. Keep it off unless a test deployment or restricted synthetic monitor needs it. |
| `E2E_TEST_EMAILS`               | Allowlists test identities and suppresses outgoing mail to them.                                                                                     |

Convex provides `CONVEX_SITE_URL`. The frontend reads `VITE_CONVEX_URL` from
`.env.local`.

## Project structure

```text
convex/          Convex schema, auth, schedules, calendar, email, and HTTP code
e2e/             Playwright multi-user browser scenarios
public/          Static assets, app icons, web manifest, and /llms.txt
scripts/         Test-environment checks
shared/          Framework-independent schedule and decision validation
src/components/  Shared React components
src/routes/       TanStack Router pages
src/scheduling/   Client-side schedule draft state
tests/            Shared-domain and React component tests
```

The main routes are `/` for the dashboard, `/new` and `/new/decision` for
creation, `/s/:slug` for a schedule, and `/d/:slug` for a decision.

## Email requests

JRNY Plan can create a schedule, a standalone decision, or a schedule with
attached decisions from a structured plain-text email. The sender must already
have a verified JRNY Plan account. The deployed `/llms.txt` endpoint publishes
the current inbox and request format when AgentMail is configured.

The protocol uses one JSON object between `JRNY_SELECT_REQUEST_V1` and
`END_JRNY_SELECT_REQUEST`. The legacy marker names remain stable so existing
clients do not break after the product rename.

See [the email request architecture decision](./docs/adr/0001-authenticated-email-schedule-requests.md)
for the trust model and processing rules.

## Testing

### Run local checks

The unit and backend suite needs no provider credentials or running Convex
deployment:

```bash
npm test
```

Run coverage, lint, and the production build before sharing a change:

```bash
npm run test:coverage
npm run lint
npm run build
```

Global line and branch coverage must remain at 85% or higher.

### Set up browser tests

Browser tests use three reserved `.test` identities and the test-only password
provider. Do not reuse personal credentials.

1. Copy the example runner configuration.

```bash
cp .env.e2e.example .env.e2e.local
```

2. Replace the password placeholders in `.env.e2e.local`. Keep the email
   addresses distinct and synchronized with the Convex allowlist.

3. Enable the identities on your development deployment.

```bash
npx convex env set E2E_PASSWORD_AUTH_ENABLED true
npx convex env set E2E_TEST_EMAILS 'host@example.test,guest@example.test,guest-two@example.test'
npx convex dev --once
```

4. Install the blocking browser once, then run the suite.

```bash
npx playwright install chromium
npm run test:e2e
```

Playwright starts the local Vite server when `E2E_BASE_URL` is
`http://localhost:3000`. The first run creates the allowlisted accounts. Later
runs reuse them and create uniquely named fixtures.

After local browser work, disable test sign-in:

```bash
npx convex env remove E2E_PASSWORD_AUTH_ENABLED
```

See [the end-to-end testing guide](./docs/e2e-testing.md) for email suppression,
the second participant, and the Google Calendar boundary.

## Build and deploy

Create the production bundle, then deploy the static client:

```bash
npm run build
npm run deploy
```

The Vite configuration prerenders `/` and emits an SPA fallback. Convex Static
Hosting serves the frontend after the exact authentication, calendar, webhook,
and `/llms.txt` HTTP routes.
